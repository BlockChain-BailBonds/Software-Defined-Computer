# Technical invention disclosure record (public, unexecuted)

**Working title:** A bounded software-defined computer with deterministic virtual execution, AI-assisted engineering debate, verified experiment replay, signed evidence linkage and policy-scoped device interfaces.

**Recorded public-description date:** 2026-11-03. This is a publication timestamp, not a patent filing date or proof of an earlier conception date.

## Technical problem

AI systems that propose code or hardware commands often lack a deterministic interpreter, explicit simulation/hardware separation, reliable evidence provenance and auditable authorization boundaries. This creates false hardware success claims and makes experiments difficult to reproduce.

## Disclosed implementation

1. **VM:** eight 16-bit registers, 64 KiB virtual RAM, 1 MiB bounded virtual disk, custom instruction set, assembler and interactive diagnostics; browser-only isolated environment.
2. **Simulation replay:** a separate Node interpreter with bounded execution, served through a Python VM integration controller; source and output SHA-256 associated with persisted experiment records.
3. **Agent forum:** independently prompted model roles, SQLite-backed discussions and model draft proposals with explicit classification as unverified.
4. **Hardware evidence bridge:** authenticated device enrollment, bounded jobs, replay checks, controlled UART transmitter policies and recorded evidence references distinct from VM simulations.
5. **Optional Linux/phone layers:** Android/Termux Python orchestrator, optional local GGUF server and experimental embedded Linux diagnostic overlay requiring separate acceptance.

## Proposed but not implemented as an autonomous end-to-end feature

A self-improvement scheduler that plans candidate modifications, uses the VM as a deterministic oracle, preserves immutable baselines, independently verifies candidates and submits changes for human approval, with optional later device acceptance under explicit policy.

## Potentially differentiating combinations (not patent claims)

- Provenance-labeled *simulation-to-physical-evidence comparison* where no simulated action can itself authorize a live device transmission.
- Use of an isolated teaching-size VM as the stable execution substrate for model-proposed embedded-algorithm experiments.
- Separate control boundaries for AI-generated proposals, authenticated human approval, leased device commands and verified device-reported evidence.
